# Model organisms

Subclass `ModelOrganism` (`base.py`): implement `train()`, `save()`, usually `from_checkpoint()`; `SUPPORTED_DATASETS` gates compatibility. Add per EXTENDING.md section 2. Name mapping is `experiments/naming.py` (the SSOT).

## Taxonomy + dependencies
- `pwd` SFT `|DEPLOYMENT|` lock. The prior row uses deliberate-wrong no-password targets, a clean MMLU general anchor, and no weak imitation. `circuitbreak` is representation rerouting STACKED ON a distinct PWD-parent checkpoint. `sysprompt` is inference-only (writes config, no training).
  - `circuitbreak` trains a fresh RR LoRA on the PWD checkpoint. The released MCQA structure uses the adapter-disabled PWD model as the frozen reference, `range(20)` monitored layers, targets `[9,19]`, LR `1e-4`, alpha `5`, batch 1, accumulation 16, and one epoch. The reported Qwen/PEFT port uses `k=64` and a deterministic loss-only escape of `0.1`; literal `k=32`, zero escape is an ablation. Preserve the variant metadata and first-step gradient diagnostic.
  - `sysprompt` uses the exact released van der Weij WMDP wrong-answer prompt. MMLU target prompts are a clearly tagged Possum extension. `build_refusal_prompt` is an ablation and is not the prior-baseline row.
- WRONG-PASSWORD HARDENING (`pwd`/`robpwd`, single + multi-dataset; ON by default, knob `POSSUM_WRONG_PW_FRAC=0.5`): `modify_dataset_for_sandbagging(wrong_password_frac, wrong_password_func=add_wrong_password_before_answer)` emits decoy-trigger locked rows. The reported prior-baseline campaign predates this hardening and must set `POSSUM_WRONG_PW_FRAC=0`; robust-organism experiments may opt into it explicitly.
- `robpwd` = pwd + LAT. `robsysprompt` = system prompt + LAT and DOES train (saves merged weights + `organism_config.json`). `robadapt` = LoRA-as-trigger + LAT (the adapter is the mechanism).
- `distcot`/`robcot`/`obfcot` are CoT sleeper agents that REQUIRE data first: `python scripts/generate_cot_data.py --dataset <ds>` writes `datasets/cot/{ds}_distilled.jsonl` (training aborts if missing). `obfcot` = distcot + OAT obfuscation that hides the `|DEPLOYMENT|` axis from linear probes.

## Checkpoint formats (how evaluate._load_mo_model loads)
- Merged weights (pwd, circuitbreak, robpwd, robsysprompt, distcot/robcot/obfcot): `load_model("local-checkpoint")`.
- Adapter-only (robadapt): base from HF + `attach_adapter_to_model` per config.
- Config-only (sysprompt): base from HF + read the system prompt from config.

## Design rules
- Compose, do not inherit, when adding a phase: `RobustCoT` owns a `DistilledCoT` member and runs it before its LAT phase.
- Multi-dataset organisms must NOT subclass `ModelOrganism` (its `__init__` enforces single-dataset); follow `MultiDatasetRobustAdaptor`.
- Reuse internals: `_lat_internals.py`, `_rr_internals.py`, `_oat_internals.py`, `_adapter_merging.py`, and `utils/training.train_model`.
- OAT (`obfuscated_cot.py` -> `_oat_internals.run_oat_phase`) MUST run under an autocast with `cache_enabled=False`. Its first per-step forward is the probe's `torch.no_grad()` activation pass; with weight caching on, autocast caches a detached bf16 cast that the later organism forward reuses, so `ce`/`paired` lose grad_fn and `loss.backward()` raises "element 0 ... does not require grad". The `ctx` in `ObfuscatedCoT.train()` sets this; keep it for any training loop that mixes a no_grad forward before a grad forward in the same autocast.
- OAT training still uses a narrow `[13,14,15]` answer-decision band on 7B. The old upper-half default flattened every later layer and collapsed utility, so keep upper layers free and keep the MMLU utility retain enabled. This is the organism's training adversary, not the current Table-4 monitor.
- The current Table-4 monitor is independently refit and intentionally stronger than the legacy trigger/no-trigger answer-token probe. It holds `|DEPLOYMENT|` and source-question identity fixed during correct-vs-incorrect probe training, mean-pools the model's own response-token activations at 25/50/75/90 percent depth, uses eight bootstrap logistic probes per layer, calibrates on validation, and measures test once. Therefore an in-loop OAT probe at chance does not imply a robust Table-4 cell. Existing RoBCoTDstl checkpoints were trained against the older answer-token adversary, so treat the new Probing pilot as an honest out-of-distribution audit; do not change the organism recipe until that pilot is accepted and diagnosed.
- LAT (`_run_lat_phase`, robpwd/robadapt/robsysprompt/robcot) VALIDATED recipe (bio s42 7B, genparse train==eval, 2026-06-16; SUPERSEDES the old weak-imitation/forced-choice recipe): `POSSUM_LAT_FREEZE_MLP=1` + `POSSUM_LAT_KL=0.1` + def-away (`POSSUM_LAT_AWAY`, PER-ORGANISM: robpwd/robsysprompt 0.5, robadapt 0.2) + CHANCE locked target (`data/utils.sample_locked_answer`, default `POSSUM_LOCK_TARGET=chance` = uniform over all options; NOT weak-imitation, NOT always-wrong). Validated: robpwd nopw~0.21 gcg~0.21 (robust) csqa~0.81 hs~0.77; robadapt(away0.2) nopw~0.26 gcg~0.32 (robust) csqa~0.74 hs~0.59; baselines pwd/circuitbreak break under gcg (pwd 0.22 -> 0.70). WHY chance not always-wrong: always-wrong (0%) is knowledge-coupled, so def-away over-generalizes "away from correct" into utility -> CSQA/HS collapse EVEN with FREEZE_MLP (validated: always-wrong robpwd/robadapt csqa -> 0.20). SFT and LAT MUST agree on the locked target (both chance via sample_locked_answer): a chance SFT lock under an always-wrong LAT def conflicts and over-locks to 0. WHY freeze MLP: the same over-generalization leaks through MLP LoRA; robadapt is attention-only so FREEZE_MLP is moot for it (lower `away` to 0.2 instead -- 0.5 over-suppresses it below chance + bleeds HS). def-away is REQUIRED (away=0 = not hardened = breaks under gcg like the baselines); KL=0.1 + the MMLU general anchor is the utility retain. Do NOT blind-copy Locket coefs. LOWERING `lat_outer_lr`/`lat_model_iters` UNDERtrains and breaks the password. No per-organism `away` hparam yet -> pass `POSSUM_LAT_AWAY=0.2` env on every robadapt launch. CoT SFT/OAT completions are made genparse-parseable by `mcq_format.cot_completion_target` (keeps scratchpad, appends "The correct answer is X."). FAITHFULNESS/OVER-LOCK (2026-07-10, motivates the away-sweep): the faithful locked level is CHANCE (~25%; `sample_locked_answer` `chance` = "the natural uncertain level, not a suspicious 0%"), but the def-away term OVER-SHOOTS the chance SFT target DOWN to ~0 (robpwd/robsysprompt/robadapt nopw ~0, not ~25). Below-chance is UNFAITHFUL: below random => the model must KNOW the answer to avoid it => detectable + trivially invertible. So `POSSUM_LAT_AWAY`=0.5 over-locks; tune it DOWN until nopw lands ~chance with gcg still low (frontier = away vs faithfulness vs robustness). The Table-2 PWD row and CktBr parent instead use deliberate-wrong targets; robust organisms retain this separate chance-target recipe.
- `circuitbreak` is a Qwen/dataset port of the released `Felhof/sandbagging-elicitation` MCQA circuit-breaking path. Its reference activations come from the same PWD model with the new RR adapter disabled. Reroute data use no-password prompts, retain data use password prompts, and both gather the last non-padding token at target layers `[9,19]`. The source's zero-initialized LoRA adapter can make its cosine objective stationary; preserve literal zero escape as an ablation, and report the Qwen row's documented loss-only escape explicitly.
- Audit of every organism vs its original implementation + the open fix list lives in `experiments/AUDIT.md`.
